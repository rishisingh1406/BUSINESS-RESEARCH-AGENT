    vector_cosine_ops with m=16, ef_construction=128.

KNOWN FRAGILITIES
-----------------

1. TEST_DATABASE_URL and Redis are session-scoped. Every new PowerShell
   window starts blank. Suggest a setup-env.ps1 script, dot-sourced per
   session:
       $line = Get-Content .env | Where-Object { $_ -match '^DATABASE_URL=' } | Select-Object -First 1
       $dbUrl = ($line -replace '^DATABASE_URL=', '').Trim('"').Trim("'")
       $env:TEST_DATABASE_URL = $dbUrl -replace '/business_research$', '/business_research_test'
       docker start business-research-redis | Out-Null

2. sentence_transformers is imported at module scope in
   embedding_service.py. This costs 20-25s per pytest session even for
   tests that never touch the model. Moving the import into
   _get_model() with a TYPE_CHECKING guard fixes it (~5 lines).

3. Chunk IDs are UUID4 (per ADR-002). Deterministic IDs remain
   deferred. replace_document_chunks makes retries safe despite this,
   because it deletes then reinserts in one transaction.

4. Registration -> Redis enqueue is still not atomic (Day 15 handoff,
   section 3). A document can be registered in Postgres with no
   corresponding Redis job if enqueueing fails. Not addressed in Day 16.
   Options on the table: defer / reconciliation sweeper / transactional
   outbox. No decision made.

     Wires: RedisIngestionQueue, PostgresRegistrationStore,

     After pipeline.process returns COMPLETED:
         chunks = chunk_store.load_collection_chunks(collection_id)
         vectors = embedding_service.embed_texts([t for _, t in chunks])
         embedding_store.insert_embeddings(
             model_name,
             [ChunkEmbedding(chunk_id, vector) for ...]

     This is where the cascade invariant matters: replace_document_chunks
     deletes old chunks (which cascades away old embeddings), so
     inserting embeddings after processing never sees stale rows.
